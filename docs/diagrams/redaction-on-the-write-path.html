Workflow · agent-memory-workflow

Redaction on the write path, not after the leak

The failure is specific: an agent finishes a debugging session, writes a memory page, and the page contains the environment variable it was reading. That page is searched by every future session, mirrored into a wiki, and in the bad case pushed to a public repository — so the redactor runs before the page is stored, not after somebody notices.

8 shapes recognised · the report carries kind and length and never the value · idempotent, because a page is rewritten
Why kind, not value

A report that quotes the secret is a second copy of the secret in a second place. Kind and length are enough to know that a rotation is owed, and nothing in the report is worth stealing.

Why idempotent

A memory page is re-read, re-summarised and written again. The first version redacted its own marker on the second pass; the tests caught it, and now the marker is a shape the rules ignore.

Why the false positives matter

A redactor that mangles the sentence "the token is required" or an example reading API_KEY=changeme gets switched off, and then nothing is redacted at all.
